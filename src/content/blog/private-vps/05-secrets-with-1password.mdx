# Passing project secrets from 1Password to the VPS

*Part 5 of 7. [Previous: Rex and previews](04-rex-and-private-previews.mdx) · [Series index](README.mdx) · [Next: the Amp runner](06-amp-runner-and-deployments.mdx)*

An application may need a database password or API token. I keep those values in 1Password and send a job the field it needs from my Mac. I approve the read locally, and the value travels over the SSH connection configured in part 2. The VPS does not need a credential that can read the whole vault. The example below uses a harmless marker to check that route before supplying an application credential.

## Send a value to a job

Install the 1Password CLI on the Mac and enable its [desktop app integration](https://developer.1password.com/docs/cli/app-integration/). A secret reference identifies a vault item and field:

~~~text
op://Engineering/Transport check/value
~~~

Here, `Engineering` is an example vault, `Transport check` is an item and `value` is its field. The CLI's [`op read` command](https://www.1password.dev/cli/reference/commands/read) resolves that reference. Its `--no-newline` option returns the value without adding a line ending. Use a separate credential for each application's needs. An application's database password should not be the VPS recovery password under a different name.

Before sending a real credential, create a test field containing `transport-check-only`. The example receiver runs a fixed container job that checks this marker and prints a success message. It accepts exactly one field, `DEMO_TOKEN`. Download [receive-demo-job.py](/examples/private-vps/receive-demo-job.py) and [send-demo-job.py](/examples/private-vps/send-demo-job.py) to the Mac and inspect both. Edit the sender's reference to match your test item, treating real vault and item names as private configuration.

From the directory containing the downloads, install the receiver under `builder`:

~~~sh
ssh workbench 'install -d -m 700 /home/builder/.local/bin'
scp receive-demo-job.py workbench:/home/builder/.local/bin/receive-demo-job
ssh workbench 'chmod 700 /home/builder/.local/bin/receive-demo-job'
~~~

The sender runs `op read` on the Mac and sends the result as JSON over SSH's standard input. Its command line names the receiver without containing the retrieved value. The receiver validates the request and passes `DEMO_TOKEN` to a rootless container through its environment.

Run the sender on the Mac:

~~~sh
python3 send-demo-job.py
~~~

Approve the 1Password request. Expected output:

~~~text
transport check passed
~~~

The job should not print the marker itself. If the vault read fails, the sender stops before starting a remote job.

## Use the pattern for an application

For an actual job, replace the fixed image and command with the application you intend to run, and define the specific environment names it may receive. The receiver rejects extra fields and limits the request size; keep those checks when adapting it. Accepting names such as `DOCKER_HOST`, `PATH` or `PYTHONPATH` could change the launcher itself, so a general-purpose list of uppercase names is not enough.

The same principle applies if you add a project mount. Resolve it beneath the intended projects directory, check where symlinks lead and pass commands as argument lists rather than assembling a shell command.

Sending the value through standard input keeps it out of SSH command arguments and avoids a helper-created temporary file. It still exists in process memory and in the container's environment configuration. The development account owns the Docker daemon and can inspect its containers. That includes the Amp host runner, which uses the same account. A container without a Docker socket does not hide its credentials from the daemon's owner or the host administrator.

Keep application logs free of credentials too. For a persistent service, decide how its secret will be stored or fetched at startup, including after a reboot. This one-job workflow keeps broad vault access on the Mac; it does not supply automatic secret renewal to every application.
