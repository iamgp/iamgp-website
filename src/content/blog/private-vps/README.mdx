# Building a private development VPS

I wanted a development machine I could leave running and return to from my Mac or iPhone. This series explains how I put one together, with Rex for remote terminals, Tailscale for private access and an Amp runner for development and deployments. The VPS runs projects independently of the laptop, with private HTTPS previews. I use 1Password to hold the access credentials and project secrets.

## What you need

The guide starts with a fresh Ubuntu 24.04 LTS VPS and working access to your provider's browser console. You should be comfortable using a terminal and editing configuration files. You will also need Tailscale on your Mac and iPhone, 1Password on the Mac and an Amp account. ## Names used in the examples

The server names and vault references are examples. Replace them with your own values.

| Name | Meaning |
| --- | --- |
| `workbench` | The VPS's operating-system Tailscale node, SSH alias and Amp runner name |
| `workbench-rex` | Rex's separate Tailscale node on the same VPS |
| `builder` | The development account, which owns projects and user services |
| `operator` | The administrator account, which can use sudo |
| `YOUR_TAILNET` | Your Tailscale DNS suffix, without the final `.ts.net` |
| `YOUR_TAILSCALE_LOGIN` | Your user identity as shown in the Tailscale admin console |
| `MAC_TS_IP`, `MAC_REX_TS_IP`, `PHONE_TS_IP` | Your devices' Tailscale addresses. Omit the Mac Rex address if you do not use its embedded integration. |
| `YOUR_AMP_USER_ID` | The intended account's ID from `amp account list` |
| `Engineering` | The example 1Password vault |

Uppercase placeholders need replacing before you run a command or save a policy. The posts identify where commands run. Addresses such as `127.0.0.1` and the port ranges are configuration examples you can keep.

The linked vendor documentation covers installation details that may change. The [example files](/examples/private-vps/README.txt) contain the longer scripts and policy used in the posts.
